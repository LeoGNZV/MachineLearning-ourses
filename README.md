# MachineLearningCourses
Поставлена задача классификации. Имеющийся датасет посвящён персонажам, которых создавали люди для настольной ролевой игры Dungeon&Dragons. В ходе работы будет изучено по каким отличительным признакам можно определить класс конкретного персонажа. 

### Подробная информация содержится внутри файла с кодом

### Краткая сводка
* Объём данных: 1,204,252. ~900,000 после очистки
* Количество признаков: 11
* Количество классов: 14
* Типы признаков: присутствуют числовые, категориальные и текстовые признаки, а также data_time
* Наличие пропущенных значений: есть
* Сбалансированы ли классы? Классы не сбалансированы
* Диаграммы рассеивания и матрица корреляции. 
Матрица коррелляции наглядно показывает зависимость между базовым здоровьем, стартовым уровнем персонажа и текущим уровнем. Небольшая коррелляция между характеристиками strength и constitution также выглядят логично, так как игроки, создающие бойца ближнего боя вынуждены не только прокачивать силу, от которой зависят удары оружием, но и телосложение, которое позволит "впитать" больше урона
По графикам был обнаружен большой правый хвост у базового хп. Распредление характеристик между разными классами отдалённо напоминает нормальное распределение
* Предобработка. Слияние классов, исходные данные были не точны. Дважды два одинаковых класса назывались по-разному. Убирал неточности и опечатки в названии рас, убирал невозможные числовые значения: здоровье равное нулю и ниже него, характеристики вне диапазона от 1 до 30.
* Для метода LogisticRegression была проведена нормализация, так как наблюдалось большое различие порядков на исходных данных, к чему этот метод чувствителен. Для RandomForest нормализация не обязательна, но она ничему не вредит.
* В моей задаче присутствует несбалансированность классов. При запуске методов был использован параметр class_weight='balanced'. Он гарантирует более редким классам больший вес в функции потерь. Благодаря этому модель не игнорирует редкие классы.
* Был осуществлён запуск Линейной регрессии для определния количества золота, предсказания были не успешны, что объясняется игромеханически, само выделение средств в игре определяется человеческим фактором - выбором мастера игры
* Для классификация классов персонажа были запущены: 
LogisticRegression: 'train_acc': 0.482, 'test_acc': 0.483, 'test_f1_macro': 0.438. Недообучена: линейная граница не улавливает нелинейности. Train ≈ test (разрыв < 0.005) — нет переобучения.

RandomForest:  'train_acc': 0.972, 'test_acc': 0.883, 'test_f1_macro': 0.863. Лучший результат, но переобучена (train 0.972 vs test 0.883, разрыв 0.089).

Accuracy - количество успешных предсказаний из общего числа. f1_macro - среднее количество f1 по всем классам f1 строится для конкретного класса. Это 2 умножить на произведение полноты и точность, а также на сумму полноты и точности, где точность - количество точных угадываний класса к общему числу предположений о конкретном классе, а полнота - количество точных угадываний класса к сумме первого, а также ошибок модели, когда она предположила другой класс. f1_weighted - f1 взвешенное по частоте классов
